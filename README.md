## `$ whoami`

I am a Computer Engineering student focused on production-oriented LLM systems, agentic workflows, local inference, computer vision and robotics. My main interest is the engineering layer between a convincing model demo and software people can actually depend on.

I work across retrieval quality, latency, evaluation, failure modes, GPU constraints, model serving and maintainability. I am especially interested in systems where language models must retrieve context, use tools, make grounded decisions and interact with users or the physical world.

## 🧠 Systems Focus

### LLM runtime & on-prem inference

I work with local and hosted models, privacy-conscious deployment, model serving and hardware-aware optimization. **ARGUS** is the center of my systems work: an LLM runtime engineering project exploring KV-cache behavior, GPU memory pressure, quantization, paging and practical inference constraints. The work spans C++, CUDA and Triton, runtime integration and reproducible benchmarking—without treating a single synthetic result as a production claim.

### RAG, agents & applied AI

I design retrieval pipelines and tool-using agent workflows with grounding, memory and evaluation in mind. The goal is not a one-off impressive response; it is a system that retrieves the right context, selects the right tool, recovers from failure and produces an inspectable result.

### Robotics, vision & real-time interaction

My work also covers YOLO training pipelines, simulation-based robotic control, speech analysis and real-time avatars. I enjoy projects where AI leaves the chat window and must deal with perception, planning, timing, visual input or human interaction.

## 🚀 Selected Work

- **ARGUS — LLM runtime engineering:** investigating KV cache, GPU memory, quantization, paging and inference bottlenecks through C++/CUDA/Triton integration and reproducible benchmarks.
- **RoboTeach — LLM-controlled robotics:** a public graduation project connecting LLM reasoning with policy-based robot control inside a PyBullet simulation environment. The Python system separates simulation, planner, perception, skills and evaluation modules, with NumPy and Groq in the verified stack.
- **Multi-tenant Restaurant AI Assistant:** an AI service assistant for restaurant brands such as Özsüt, Taşocak and Simit Sarayı, using a central LangChain-style agent/node architecture and business-specific tools to take customer orders in natural language.
- **Real-Time AI Avatar:** technical mentorship for a system combining speech, voice, lip-sync and GPU-backed real-time avatar delivery for more human-like service interactions.
- **Reading Analysis:** a research-oriented system comparing children’s reading audio with reference speech to analyze reading differences and performance.
- **Accessibility Assistant:** an accessibility-focused university assistant for visually impaired users, developed as a real-world project that received press coverage.
- **UAV / YOLO Pipeline:** a computer-vision training workflow covering dataset preparation, YOLO training and evaluation for an unmanned aerial vehicle scenario.
- **AI Product Systems:** document and presentation generation plus AI-assisted content workflows for ideation, scripts, thumbnails and teleprompter-style production.

## ⚙️ AI-Native Development

I used to write software manually before agentic coding became common. Today I use coding agents heavily for implementation, refactoring, testing, debugging and exploration, while keeping architecture, system design, evaluation and technical decisions human-directed.

This is **agent-assisted engineering** and **agent-orchestrated development**: agents accelerate execution, while I remain responsible for system boundaries, integration risks, benchmarks and final judgment. AI-native development is not a replacement for understanding the system; it is an engineering multiplier.
